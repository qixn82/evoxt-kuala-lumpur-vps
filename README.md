## 为什么机房要放在吉隆坡，而不是拿新加坡凑合

很多面向马来西亚的中文站点，服务器放在新加坡，测速看起来还行，本地用户打开却是 80–120 ms。问题出在路由：流量先从新加坡绕到香港，再回吉隆坡，物理距离很近，路径绕了半个东南亚。

Evoxt 在吉隆坡的节点放在 AIMS KL2，这是一座 Tier III 数据中心；它自己持有 ASN **AS149440**，运营自有网络而不是租别人的 BGP；同时在 **MyIX（马来西亚互联网交换中心）** 与本地主要 ISP 直接对等，并与 Google、Cloudflare 建立直连。这三件事叠在一起，决定了马来西亚境内用户的请求在本地就完成交换，不用出境再回来，境内访问延迟通常落在个位数到十几毫秒的量级。

横向参考一下本地网络的大致水平。另一家吉隆坡服务商 Vebloom 公布过一组从吉隆坡出发的延迟数据：吉隆坡本地约 2 ms、槟城约 8 ms、新山约 10 ms、新加坡约 10 ms、曼谷约 25 ms、雅加达约 30 ms、胡志明市约 35 ms、香港约 40 ms。这是那家厂商自己公布的数字，不是 Evoxt 的实测结果。它能说明的是一件事：吉隆坡作为机房位置，覆盖马来西亚全境和新加坡都在 10 ms 上下，做东南亚区域站而不是只做马来西亚，位置也站得住。

## 6.0 GHz 的单核，什么场景才用得上

Evoxt 官方对全系 CPU 的表述是“最高 6.0 GHz+”，卖点写在“用低频 CPU 的价格买高频 CPU”。第三方测评机构 VPSBenchmarks 的独立测试把它排进单核性能靠前的一档；这个结论是第三方给出的，不是厂商自评。

单核主频高的实际收益集中在这么几类负载上：没做页面缓存的 WordPress 和 WooCommerce，PHP 请求全程单线程跑完；Discuz、Flarum 这类论坛的首屏渲染；小型 MySQL 或 PostgreSQL 数据库的单查询；以及 MySQL 之外的游戏服，像 Minecraft、Palworld 这类对单线程 tick 敏感的服务。这些场景里，8 核 2.4 GHz 的机器往往打不过 2 核 6.0 GHz 的机器。

反过来，视频转码、大批量图片压缩、持续高并发的 API 网关，靠的是核数和并行度，这时候 VM-6 以上的档位才有意义，单核频率带来的差别会被摊薄。
